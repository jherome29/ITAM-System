## Missing — the business logic, not the plumbing

This is the real gap. The data model and CRUD exist; the *rules* CICC actually needs mostly don't:

- **System Configuration is now real — built on `feature/system-config`, PR pending (not on `main` yet).** New `system-config` backend module: a key-value `system_config` table (migration `Database/schemas/006_system_config.sql`), `GET`/`PATCH /api/v1/system-config` (SYSTEM_ADMIN only, audited as `SYSTEM_CONFIG_UPDATED`), a cached `SystemConfigService` with compiled-in fallback constants, and four runtime-tunable settings — SLA approval hours, default reorder level, useful-life-years per class, max login attempts — consumed live by `requisitions.service` (SLA deadline, breach/nudge, replacement validation), the low-stock watcher, and `auth.service` (lockout). The UI is **Master Admin → System Settings** (`SystemSettingsPage`, `/master-admin/configuration`) — real `systemConfigApi` load/save, load-error retry. The old `/admin/config` page was deleted (the redesigned Master Admin layout is the one in use). **Remaining follow-up:** `SystemSettingsPage`'s aspirational tabs (numbering / notification routing / forms & print / data retention / localization) are honestly labelled "not yet configurable"; deferred settings not in scope this round: approval routes, session policy, PPE cost threshold. Verify against that branch, not `main`.
- **Notifications now fire — built 2026-08-27 on `feature/notifications-auto-fire-sla-cron`, PR pending (not on `main` yet).** A `scheduler` module with `@nestjs/schedule` cron watchers auto-creates: SLA breach (>24 h approval), 12-hour pending-approval nudge, overdue return (with `expectedReturnDate` set on ISSUED + re-arm), and low stock (reorder-level threshold + re-arm). Dedup stamps prevent repeat firing; an admin `run-checks` endpoint triggers a pass on demand. Verify against that branch, not `main`.
- **SLA enforcement — same branch/PR as above.** `checkSlaBreaches()` is now invoked by the scheduler's SLA watcher, fires once per breach, and reaches the oversight roles (System Admin + Management). Was previously dead code.
- **Replacement requisitions aren't validated.** The system is supposed to check useful-life, condition, or loss/damage before approving a "replacement" request — confirmed `create()` treats `RequisitionType.REPLACEMENT` identically to `NEW`, no lookup of the asset being replaced, no criteria check at all.
- **Disposal is a status flag, not a workflow.** Flagging an asset "for disposal" just changes its status. There's no required justification, condition assessment, or recommended-action fields actually enforced.
- **No alternate approver support.** Documented as a requirement; doesn't exist in the data model or anywhere in the code.
- **No physical count / reconciliation.** Worse than just "no UI for it," and the two forms fail differently: `RPCI`'s "count" columns are hardcoded (`QTY PER CARD` and `QTY PER COUNT` both always `'1'`, shortage/overage always blank), so it fakes a reconciliation instead of doing one. `RPCPPE` doesn't even attempt that — it has no card/count/shortage/overage columns at all, just a plain asset listing. Either way, there's no mechanism anywhere to actually record a count and compare it against system records.
- **2 of 8 management reports don't exist**: Asset Utilization Summary and Audit Trail Report (as an export — the live audit log itself works).
- **All 18 generated COA forms diverge from their official templates, checked and confirmed for every one** — full breakdown in `docs/guides/COA-FORMS-AUDIT.md`. Roughly a third are close (RIS, RSPI, RSMI, PTR — right signatory count/roles, minor field gaps). Most add an unofficial extra signature block the shared template defaults to, that the real form doesn't have (PAR, ICS, IAR, both Receipt-of-Returned forms, RLSDDP). A few are more seriously off: WMR is missing an entire required section (Certificate of Inspection — disposition method, witness signature); IIRUP drops its accounting columns and required Witness signature; Move-In/Move-Out have wrong attachment options and a **hardcoded Property-Type checkbox that always shows "Office" even for personal items** — a real bug, not just formatting. Sticker Card isn't even the right *document* — Appendix 58 is officially a Stock Card (a receipt/issue ledger), the generator makes a physical asset tag instead. These are real government forms; an auditor comparing output to the official template would notice immediately.
- **RSMI report zeroes every cost figure.** `reports.service.ts` hardcodes `acquisitionCost: 0` when building RSMI data, even though the real cost is one join away via the requisition item's fulfilled asset. Every RSMI ever generated shows ₱0.00 unit cost, amount, and total — on an official COA financial supply-issuance report.
- **Management dashboard mixes real KPIs with unlabeled hardcoded chart data.** The four stat cards and SLA panel are real (`GET /v1/reports/kpi`). But "Monthly Requisition Trends" and "Asset Utilization by Category" are entirely static mock arrays, styled identically to the real panels next to them — nothing in the rendered UI distinguishes live data from numbers that never change.
- **Fire-and-forget audit logging on the most security-sensitive auth events.** Failed login, account lockout, refresh-token reuse, and logout in `auth.service.ts` use un-awaited, uncaught promise calls to the audit logger (unlike every other audit call in the codebase, which is properly awaited). If the DB write fails at that exact moment, the audit entry silently never exists with nothing pointing at why. Lower urgency than the items above — only surfaces during a DB blip at the exact moment of a security-relevant event.
- **Redesigned-layout wiring is done** (2026-08-27, on `main`) — the Property roles' screens, IT Asset Custodian, Approving Officer, Management & Audit, and Master Admin's Users/Roles/Audit are all real now. What's left is the no-backend screens listed under "Solid" above and detailed in `MOCK-DATA-WIRING.md` — Master Admin governance, `admin/config`, physical count, Property Officer corrections/reconciliation/replacements, Employee returns/incidents.

## What's actually solid despite the gaps above

Forms/reports generation *mechanism* is in good shape — all 18 forms generate real PDFs from real data, correctly stored and re-downloadable, no crashes. Whether each form's actual *layout* matches its official COA template is a separate, weaker claim — see the forms-fidelity gap above.

Of the 6 "wired" management reports: **Asset Master List, Requisition History Log, and Disposal Documentation Report are genuinely solid** — they query exactly what they claim to. **Asset Issuance Record and Asset Return Record have a real, quieter gap**: both filter assets by *current* status (`WHERE status = 'issued'` / `'returned'`) rather than by historical event, so an asset that was issued and later returned silently disappears from the "Issuance Record" — it's a snapshot of current state mislabeled as a historical log, not an actual record of issuance events over time. **Physical Count Summary confirms the already-known gap exactly** — it's a plain `SELECT * FROM assets`, no count/reconciliation logic at all, same root cause as RPCI/RPCPPE above.

## Fixed 2026-08-21 — dead controls, a backend crash, and a systemic enum-casing bug class

Two rounds of a systematic parallel-agent audit (5 domain sweeps each round, covering every role's frontend plus all 8 backend controllers), on branch `fix/dead-ui-controls-and-logout-crash` off `develop`. Round 1 looked for dead/fake UI controls (the same pattern as the Approve/Reject fix above); round 2 additionally checked whether code that *does* call a real API is actually correct, which is how most of these were found — not fake, just broken.

**Round 1 — dead/fake controls:**
- `SidebarNav.tsx`'s "Sign out" was `<Link href="/login">`, not a call to the real `logout()`. Looked like a working button; actually left the session alive in memory, so `/login`'s own already-logged-in redirect bounced the user straight back. Affected all 7 redesigned role dashboards.
- `auth.controller.ts`'s `logout()` read `req.user.sub` — always `undefined`, since `JwtStrategy.validate()` attaches the full `UserEntity` (field `.id`, not `.sub`) to `req.user`. Crashed with a 500 on every real logout call, masked by the frontend bug above never actually reaching it until that was fixed. A full backend sweep confirmed this was genuinely isolated — every other controller already types `req.user` as `UserEntity` via a shared interface, which structurally prevents this class of typo.
- `RoleDashboard.tsx`'s "View All" on Recent Requisitions was a plain `<span>`, not a link.
- `AssetInventoryGallery.tsx`'s asset/property/supply registration wizard (IT Asset Custodian + Property Custodian) looked fully real — validation, photo upload, "Register record" — but silently discarded to local state with no mock disclosure, unlike every sibling mock component in this codebase. Now honestly labeled; still not wired to the real API (that's separate, larger work, not this fix).

**Round 2 — a real, live security bug plus a systemic correctness pattern:**
- **Notifications IDOR**: `PATCH /api/v1/notifications/:id/read` had no ownership check — any authenticated user could mark any other user's notification as read by guessing a UUID. Now scoped to the caller, with a regression test.
- **The pattern, found independently across ~6 unrelated files**: frontend code using uppercase status/role/action string literals (`'PENDING_SUPERVISOR'`, `'EMPLOYEE'`, `'ASSET_CREATED'`) against `packages/shared/src/enums`, which is entirely lowercase snake_case. Every instance was a real, wired feature silently broken, not a fake one:
  - `reportsApi.generate()` sent `{type, format, filters}` against a backend DTO expecting `{reportType, format}` with strict whitelisting — every report generation 400'd.
  - IT Personnel's asset detail page (`it-personnel/assets/[id]`) keyed its lifecycle-transition map uppercase — the "Update Lifecycle" button never rendered for any asset, for anyone, despite the backend being fully correct. Same file's Condition dropdown had the same bug.
  - `/admin/users/new` and `/admin/users/[id]/role` sent uppercase `UserRole` values — user creation and role assignment always 400'd. (Also fixed: the password field's client-side `minLength` said 8, backend actually requires 12 + complexity.)
  - `AuditTrailContent.tsx`'s action filter was worse than a silent no-match: `audit_logs.action` is a native Postgres enum column, so filtering threw a DB error, then a `.catch(() => {})` swallowed it and the page just went blank. Two of the filter options didn't correspond to any real enum value even case-corrected.
  - Notification-type icon lookups and the prototype `StatusBadge` dictionary both keyed uppercase/capitalized against real lowercase values — wrong icons, badges falling back to generic gray for all live data.
  - `SidebarNav.tsx` additionally showed a hardcoded fake name/initials per role instead of the real logged-in user (`useAuth()` was already available, just unused for this) — affects the real `/employee` route, not just prototype-only ones.
- **Employee's dashboard and notifications were the last mock-only Employee pages** — wired to real `requisitionsApi`/`notificationsApi`; the one section with no backend equivalent ("my assigned assets") is now labeled "Preview data" instead of presented as real.
- **Master Admin's governance/platform pages** (approval workflows, custodian assignments, master data, system health, org units, access reviews) have no backend at all to wire to — their success messages now say "...in frontend mock state," matching the sibling Settings/Security pages, instead of implying persistence.
- **The Approving Officer's live queue was silently capped at 15 records** (an unset API default) with client-only pagination on top that never re-fetched. Raised the fetch limit and added a truncation notice — true server-side pagination would need this component's search/sort to move server-side too, which is a bigger change than this fix.
- Several previously-silent `.catch(() => {})` sites (audit trail, notifications, both admin/management dashboards, the live-fetch queue) now surface a visible error instead of looking identical to "no data."

Verified: `tsc`/`eslint` clean project-wide (frontend + backend), full Next.js production build succeeds (all 39 routes), backend suite 170/170, frontend suite 23/23 — before and after each round, no regressions. `fix/dead-ui-controls-and-logout-crash` merged via PR #79/#81; now on `main`.
